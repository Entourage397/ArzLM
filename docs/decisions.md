# Engineering decisions

Recorded against **installed** packages, not memory:

- Python: 3.12.14 (uv) in `.venv`. System Python was 3.13.15 with no PyTorch. WSL Ubuntu currently has Python 3.14.4, which is a poor default for PyTorch wheels.
- PyTorch: `2.11.0+cu128` (official CUDA 12.8 wheel). Driver reports CUDA UMD 13.4; the wheel runtime is 12.8 and is compatible. GPU: NVIDIA GeForce RTX 4070 Laptop, 8188 MiB, sm_89, BF16 supported.
- LitGPT: `0.5.13`. Config fields, GPT, GQA (`n_query_groups`), QK-Norm (`norm_qk` / `norm_qk_type="default"`), `LLaMAMLP` SwiGLU, RMSNorm, SDPA (`F.scaled_dot_product_attention(..., is_causal=mask is None)`), fused AdamW, cosine+warmup (`litgpt.pretrain.get_lr`), and Fabric single-device `strategy="auto"` were verified in `.venv/Lib/site-packages/litgpt/`.
- No DeepSpeed, FSDP, bitsandbytes, gradient checkpointing, or third-party `flash-attn`. LitGPT only enables FSDP when `devices * num_nodes > 1`. This project is one 8GB GPU.
- **QK-Norm:** LitGPT implements default QK-Norm as RMSNorm of size `head_size` applied to Q and K after the `(B, n_head, T, head_size)` reshape. That is the intended QK-Norm, so it is enabled.
- **Full RoPE:** `rotary_percentage: 1.0` so `rope_n_elem == head_size`. LitGPT's default is `0.25` (GPT-NeoX-style partial rotary). We override it explicitly.
- **No parallel residual:** LitGPT default `parallel_residual=True` is GPT-NeoX. LLaMA-style sequential residual is `parallel_residual=False`.
- **Vocab padding:** LitGPT default `padding_multiple=512` would pad 32000 → 32256 and add ~2M tied embedding parameters. `padding_multiple=64` keeps `padded_vocab_size=32000`.
- **Tied embeddings:** LitGPT applies tying in `pretrain.main` via `model.transformer.wte.weight = model.lm_head.weight` when `train.tie_embeddings` is true. Parameter counting uses `litgpt.utils.num_parameters` after tying.
- **Precision:** Fabric `bf16-true` on this Ada GPU. LitGPT's default helper returns `bf16-mixed` for training; mixed keeps fp32 master weights and costs VRAM we do not have to spend on 8GB. Native BF16 is supported (`torch.cuda.is_bf16_supported()`).
- **Data format:** LitGPT OpenWebText uses `litdata` streaming chunks. `litdata` extra-depends on `uvloop` (non-Windows) and is unnecessary for local 10M–100M token files. Packed `uint16` memmaps with EOS-after-document match `litgpt.pretrain`'s `(seq+1)` batch layout and keep tokenization off the GPU step.
- **FineWeb-Edu subset:** Always `HuggingFaceFW/fineweb-edu` config `sample-10BT`, streamed. Never `default` / full dumps.
- **Tokenizer:** HuggingFace `tokenizers` byte-level BPE, 32k, files written so `litgpt.Tokenizer` loads `tokenizer.json` + `tokenizer_config.json`. `add_bos_token: false`; document boundaries are EOS only.
- **torch.compile:** LitGPT pretrain always compiles. On this host, `torch.compile(nn.Linear(...).cuda())` raised `TritonMissing` (no Triton package, no `nvcc`). Training configs therefore set `compile: false` after that measurement. `compile: auto` skips the attempt on win32 without Triton and records the reason. Do not install unofficial Windows Triton. For Inductor, use WSL2 with Python 3.12 and official Linux CUDA wheels.
- **Micro-batch:** Swept 1/2/4/8 on the RTX 4070 Laptop. Winner is **micro-batch 2** at ~19.1k tok/s (107 ms/step, 2.59 GB allocated). Batch 4 is within 0.3% on throughput but uses 4.7 GB. Batch 8 is slower and near the 8 GB cap.
- **Tokenizer corpus size:** 400k FineWeb characters produced only a 19,852 BPE vocab. 8M characters filled 32,000. Presets that train a tokenizer now request 8M characters.
- **Training loop:** Thin Fabric loop calling `litgpt.model.GPT`, `litgpt.pretrain.initialize_weights`, `litgpt.pretrain.get_lr`, `litgpt.utils.chunked_cross_entropy`, and `instantiate_torch_optimizer(..., fused=True)` on CUDA. This preserves SDPA/Flash kernels without inheriting LitGPT's unconditional compile and FSDP branch.
- **baseline-v0:** Frozen at git tag `baseline-v0` (`dc4f53bb`). Do not rewrite `docs/baselines/baseline-v0/` or the tagged architecture YAML.
- **STEM corpus math source:** FineMath-4+ (`HuggingFaceTB/finemath`, `finemath-4plus`). Nemotron-CC-Math-4plus is stronger in NVIDIA 8B ablations but the NVIDIA Data Agreement permits only *internal* training and Phi-4 cleaning may attach Phi-4 terms to a distributed model. Not used.
- **Muon (experimental only):** Vendored `SingleDeviceMuonWithAuxAdam` from [KellerJordan/Muon](https://github.com/KellerJordan/Muon) (retrieved 2026-09-08). Hidden 2D attn/MLP weights use Muon (`lr` swept, `momentum=0.95`, `ns_steps=5`, Nesterov, Jordan `max(1, rows/cols)**0.5` scale, `weight_decay=0.1`). Tied embeddings, RMSNorm, QK-Norm, and other non-matrix params stay on AdamW with the baseline recipe (`lr=6e-4`, `betas=(0.9, 0.95)`, `eps=1e-8`, `wd=0.1`). Moonlight RMS-matching (`0.2 * sqrt(max(A,B))` so Muon can share AdamW's LR) is documented but not the default; we keep Jordan spectral LRs and a small 2M-token LR sweep instead. AdamW remains the default trainer path.
- **ArzLM-300M (2026-09-10):** Same architectural family as 100M (pre-norm RMSNorm, full RoPE, GQA, QK-Norm, SwiGLU, bias-free, tied embeddings). Shape: 24 layers, d_model=1024, 16 query / 4 KV heads, head_dim=64, intermediate_size=2816, vocab=32000, context=2048. Instantiated trainable count against litgpt 0.5.13 GPT: **303,353,856**. Configs are `configs/model-arzlm-300m.yaml` and `configs/arzlm-300m-final-6b.yaml`. The 100M YAML and expected count are unchanged.
- **300M training recipe:** Effective batch 64×2048 = 131,072 tokens/update on 1×A100 40GB (microbatch 8, accum 8). Not copied from the laptop 4/8 4070 setup. Warmup 800 optimizer steps (~104.9M tokens, ~1.75% of 6B), scaled from the 50M/2B token fraction rather than old step counts. Muon 0.05 / AdamW 6e-4 / min_lr 6e-5 kept: Jordan spectral scale already width-adjusts hidden matrices. `TrainArgs.max_time=64800` ends a Modal segment with a recovery checkpoint; `final/` is written only when the 6B token budget completes. Checkpointing is token/time based (~78.6M tokens / 600 steps) plus an early 16.7M-token recovery checkpoint.
- **Tokenizer v2:** `arzlm-stem-32k-v1` trained code on ~2M chars against a 15% mixture target. For 6B we retrain `arzlm-stem-32k-v2` on a bounded 100M-char stratified sample (55/20/15/10), not the full packed corpus.
- **6B sources:** Unique packed target 6,300,106,752 tokens at 55/20/15/10. FineWeb-Edu `sample-10BT` historically had one Hub-safe shard (~0.54GB); we do not fetch unscanned FineWeb files and never fetch `data/CC-MAIN-2024-38/000_00041.parquet`. Additional general tokens come from the already-audited `HuggingFaceTB/smollm-corpus` family (Cosmopedia-v2 + FineWeb-Edu-dedup), Hub-safe files only, with document-level skips if metadata cites the denied shard. Math/code/science stay FineMath-4+, Stack-Edu+SWH, peS2o.
- **6B code fill band (2026-09-10):** Stack-Edu packing first used permissive `int_score >= 4`. After two exhausted walks of the locked 15-language shard set, committed code sat at 914,005,626 / 945,029,120 tokens (C/Go/PHP holes). The Hub card already filters at threshold 3 (`int_score` in {3,4,5}). The unused approved segment is the same locked files' permissive `int_score == 3` band, still fetched from Software Heritage, still license-gated, still blob/text-deduped. Resume keeps existing `shard-*.bin`; it does not repack the 914M. A last overflow pass may use that same band from languages already at their mix cap only to finish the 15% code quota. No new dataset, no synthetic code, no quota cut.
- **Corpus validate source vs output dups (2026-09-10):** `docs_duplicate/docs_inspected` is packer-stream exact-hash rejection (peS2o overlap), not packed-output duplication. Science recorded 867,237/3,154,665 (27.49%) source rejects after dedup already kept 2,279,924 unique train docs. Policy v2 treated that ratio as a warning and hashed per-shard EOS spans including shard-cut fragments. That false-failed general on a 6-token empty ` ```python``` ` fence. Policy v3 stitches leftover tokens across consecutive shards, warns on exact packed collisions shorter than 32 tokens, and hard-fails substantial packed-document copies. Direct scan of packed general train found 19 exact token-span collisions: 17 boilerplate spans plus two Cosmopedia-style articles (Şanlıurfa 535 tokens, sports psychology 403 tokens). Duplicate mass is 1,037 content tokens of 3.465B (~3e-7). Those copies survived because source dedup hashes sanitized *text*, not packed tokens. Repair `packed_dedupe.repair_corpus_exact_duplicates` drops later exact packed copies and any train copies of val documents. Any train/val packed-hash overlap (including short spans) is a hard failure. Checksum mismatches remain a hard failure. Deterministic `CorpusValidationError` sets `phase=blocked` and `last_error` until `VALIDATION_POLICY_VERSION` changes; a missing `state/packed-exact-dedupe.json` marker still allows one repair+retry while blocked.
- **Modal execution:** LitGPT/Fabric trainer is unchanged in role. Modal owns Image/Volumes/A100/supervisor. App `arzlm-300m-6b`, volumes `arzlm-300m-6b-data-v1`, `arzlm-300m-6b-artifacts-v1`, `arzlm-hf-cache-v1`. GPU string `A100-40GB` ($2.10/h); refuse H100, A100-80GB, and >50GB allocations. Pack/train Dict locks expire after 30 minutes without heartbeat so a crashed CPU worker cannot block resume. Truncated peS2o gzip streams skip the remainder of that shard instead of aborting science packing. Supervisor is a deployed `Period(minutes=5)`.
- **Probation param count (2026-09-10):** `verify_checkpoint_reloadable` must instantiate the GPT with tied embeddings before counting. An untied `GPT(config)` reports 336,121,856 parameters (`lm_head` + `wte`); after tying the trainable count is **303,353,856**. The 16.8M-token probation abort `parameter_count_mismatch` was that counting error, not a wrong model. Cost projection at that point was ~$72 ≤ $98. Re-evaluate that specific abort; other abort reasons stay terminal.
- **300M/6B budget gate (2026-09-10):** Workspace usage limit is $100. Autonomous continuation after a 16.8M-token probation segment of the same production run is allowed only when the projected complete-build total (metered + remaining packing + remaining A100 hours at measured post-warmup tok/s + $2 eval/export reserve) is ≤ $98. The $93–98 range is authorized; do not plan to consume through $100. Architecture, mixture, tokenizer, Muon, and GPU class stay fixed unless approved.
- **Posttrain encode + export (2026-09-12):** LitGPT `Tokenizer.encode` already returns a rank-1 `torch.int` tensor. `torch.tensor([tok.encode(...)])` TypeError-looped `posttrain` after the 6B `final/` write. Prompts must use `encode_prompt_batch` (`bos=False`, `eos=False`, shape `[1, seq]`, dtype long). Export writes weights-only `LITGPT_INFERENCE` plus `huggingface/model.safetensors`; it does not copy optimizer state and does not modify `runs/.../final/`. Packaged `tokenizer_config.json` advertises `model_max_length: 2048` without changing tokenizer.json or token ids. `posttrain` is `max_containers=1` and holds a lease so the 5-minute supervisor cannot stampede failed evals.
- **Context length (2026-09-10):** The current 6B run is **base pretraining at 2048**. Do not change packed `seq_length`, `block_size`, or `train.max_seq_length` for this build. After `final/` is written, evaluated, exported, and smoke-tested, keep that full checkpoint (model + optimizer + tokenizer + `model_config.yaml`) for a **separate** continued-pretraining stage to 4096 and possibly 8192. That extension is **not** part of the ≤$100 Modal build. Export metadata must record `base_pretraining_context_length = 2048`.
